# 交易机会评分模型

## 目标

该模型用于新建的交易机会扫描页。它不把单一的上涨、增仓或主动买入直接解释为可追入信号，而是依次回答：

1. 当前市场方向是否成立？
2. 当前是否处于合适的入场时机？
3. 是否存在拥挤或异常波动风险？

最终只输出一个入场评分 `entry_score` 和对应的入场状态 `entry_state`。

## 数据层与评分层

底层原始数据使用现有的 5m 价格 K 线、持仓量（OI）、主动买卖净流入和资金费率。价格 K 线会在各交易所内按 UTC 时间边界严格聚合为 1h、4h：只有包含完整连续 12 根或 48 根已收盘 5m K 线的桶才可用，正在形成或缺失任意一根 5m 的桶会被丢弃。

同一份 5m 价格历史因此可服务不同判断：5m 用于执行位置、时机、止损和短周期价格结构；聚合的 1h、4h 用于确认价格趋势和寻找更有意义的止盈结构。OI、净流入和资金费率不聚合，始终按既有 5m 窗口计算。

实现上，1h、4h OHLCV 在数据库中按时间桶聚合，并以桶内根数和首末时间跨度校验连续完整性；扫描接口只读取约 120 根 5m 执行 K 线及每个高周期约 72 根聚合 K 线。EMA 与评分公式仍在应用层对这些精简序列计算。

交易机会快照以最新已收盘 5m 锚点和请求的币种、交易所范围为缓存键；同一键并发请求只允许一次加载，其余请求复用结果。该接口不使用 24h 成交额，因此不会查询该聚合数据。

```text
价格、OI、净流入、资金费率
              |
      +-------+-------+
      |               |
trend_score      timing_score
      |               |
      +-------+-------+
              |
     directional_score
              |
         risk_score
              |
         entry_score
              |
         entry_state
```

对外字段如下：

```text
trend_score        趋势评分
timing_score       入场时机评分
directional_score  风险扣除前的方向强度
risk_score         风险评分，取值为 0 或负数
entry_score        最终入场评分
trend_state        趋势状态
entry_state        入场状态
```

## 公式

```text
directional_score = trend_score + timing_score

entry_score = sign(directional_score)
              * max(0, abs(directional_score) + risk_score)
```

`sign(x)` 是符号函数：

```text
x > 0:  1
x = 0:  0
x < 0: -1
```

`risk_score` 的范围是 `0..-30`。它以绝对值方式削弱方向强度，不会改变方向：

```text
directional_score = +80, risk_score = -20 -> entry_score = +60
directional_score = -80, risk_score = -20 -> entry_score = -60
directional_score = +10, risk_score = -20 -> entry_score = 0
```

最后一种情况归零并进入观望，而不是错误地翻转为做空。

## 趋势评分

`trend_score` 的范围约为 `-60..+60`，用于判断趋势方向是否同时得到价格、OI 和订单流支持：

```text
trend_score = price_trend_score
            + oi_trend_score
            + flow_trend_score
```

### 价格趋势

`price_trend_score` 的范围为 `-35..+35`。5m 价格结构使用最近 120 根已收盘 K 线，即约 10 小时：

```text
价格、5m EMA20、5m EMA60 多空排列： +/-15
EMA20 相比 12 根 5m 前的斜率：       +/-5
最近 24 根 5m 相对前 24 根的高低点结构： +/-5
```

在此基础上，聚合的高周期只对价格趋势做确认，不参与 OI、净流入、时机或风险：

```text
1h：收盘价、EMA20、EMA60 多空排列： +/-3
1h：EMA20 相比 12 根 1h 前的斜率：     +/-1
4h：收盘价、EMA20、EMA60 多空排列： +/-5
4h：EMA20 相比 12 根 4h 前的斜率：     +/-1
```

每个周期至少需要 60 根完整聚合 K 线才计算排列分数，分别对应 720 根 5m（约 2.5 天）和 2880 根 5m（约 10 天）。若有至少 72 根完整聚合 K 线，才额外计算该周期的 EMA20 斜率；不足时该项为 0，不影响其他评分。数据不足的高周期只是不贡献这部分价格分，不会导致整个标的失效。

### OI 趋势

`oi_trend_score` 的范围为 `-15..+15`，仅使用 OI 数量变化，不使用 OI 价值变化。1h 仅代表最近 12 根 5m 的计算窗口：

```text
oi_change_1h = (OI当前 - OI一小时前) / OI一小时前
```

当 OI 绝对变化不低于 `0.5%` 且价格绝对变化不低于 `0.1%` 时：

| 价格 | OI | 分数 | 解释 |
| --- | --- | ---: | --- |
| 上涨 | 增加 | +15 | 多头开仓 |
| 上涨 | 减少 | +5 | 空头回补 |
| 下跌 | 增加 | -15 | 空头开仓 |
| 下跌 | 减少 | -5 | 多头平仓 |

不满足阈值时为 `0`。OI 价值只用于交易所权重和展示，避免价格变动本身造成 OI 价值变化而被误判为增仓。

### 订单流趋势

`flow_trend_score` 的范围为 `-10..+10`。最近 12 根 5m 的净流入必须相对于同期成交额标准化：

```text
flow_ratio_1h = 1h累计净流入金额 / 1h累计成交额
flow_trend_score = clamp(flow_ratio_1h * 100, -10, +10)
```

当净流入占 1h 成交额达到正负 10% 时达到满分。绝不按净流入绝对金额评分。

### 趋势状态

```text
trend_score >= 30:  强多趋势
10 <= trend_score < 30: 多头趋势
-10 < trend_score < 10: 震荡
-30 < trend_score <= -10: 空头趋势
trend_score <= -30: 强空趋势
```

## 入场时机评分

`timing_score` 的范围为 `-30..+40`，使用最新已收盘 5m 数据。它不重新决定方向，而是判断该方向当前是否适合执行：

```text
timing_score = price_timing_score + contract_timing_score
```

### 价格时机

使用 5m EMA20 和 ATR：

```text
ema20_distance_atr = (当前价格 - 5m EMA20) / 5m ATR
```

多头趋势下：

```text
最近 12 根 5m 触及 EMA20，当前重新收在 EMA20 上方，
且距均线不超过 0.75 ATR： +30

顺趋势偏离 EMA20 超过 1.5 ATR： -20

其他： 0
```

空头趋势完全镜像：反弹触及 EMA20 后重新收在其下方为 `-30`；向下偏离超过 1.5 ATR 为 `+20`，以削弱追空分数。

### 合约时机确认

在价格回踩或反弹确认之后，使用最新 5m 的 OI 结构与标准化净流入确认：

```text
OI结构和净流入均与趋势同向： +10 或 -10
OI结构和净流入均与趋势反向： -10 或 +10
其他： 0
```

这里分数方向跟随趋势：多头确认加正分，空头确认加负分；反向信号则抵消该方向。

## 风险评分

`risk_score` 是非正数：每项风险扣 `10`，最低为 `-30`。

```text
资金费率沿当前趋势方向的绝对值 >= 0.08%
OI 数量在最近 12 根 5m 内增加 >= 6%
5m 沿趋势方向涨跌 >= 2%，或 ATR / 价格 >= 2%
```

风险并不创建反向信号，只会使 `entry_score` 靠近零。

## 入场状态

```text
entry_score >= 65:  可做多
20 <= entry_score < 65: 等待回踩
-20 < entry_score < 20: 观望
-65 < entry_score <= -20: 等待反弹
entry_score <= -65: 可做空
```

示例：

```text
强多趋势、回踩确认、OI增、主动买盘强、无风险
trend_score = +50
timing_score = +40
directional_score = +90
risk_score = 0
entry_score = +90
entry_state = 可做多
```

```text
强多趋势、价格已偏离 EMA20 超过 1.5 ATR、OI增、主动买盘强
trend_score = +50
timing_score = -20
directional_score = +30
risk_score = 0
entry_score = +30
entry_state = 等待回踩
```

## 数据完整性

至少需要连续 120 根已收盘 5m K 线、当前与前序 OI、主动买卖量、ATR 和资金费率。任一核心数据缺失时：

```text
data_status = unavailable
entry_state = 数据不足
```

数据不足的标的不进入默认候选列表。

## 交易计划价格

交易计划只为“可做多、可做空、等待回踩、等待反弹”生成，作为 Binance U 本位合约的执行参考；它不参与任何评分，也不会改变候选筛选结果。评分仍按所有启用交易所的 OI 权重聚合。

入场价使用 Binance 5m 数据：

```text
可做多、可做空：评分锚点的最新收盘价
等待回踩、等待反弹：5m EMA20
```

止损与止盈优先使用 1h、4h 的已确认结构位；摆动高低点要求左右各有 2 根 K 线确认。5m 仍用于 Binance 的实际入场价、ATR 缓冲，以及高周期结构不可用时的回退：

```text
多头止损：最近有效 1h/4h 摆动低点下方 0.25 个 5m ATR
空头止损：最近有效 1h/4h 摆动高点上方 0.25 个 5m ATR
高周期无有效结构：回退最近有效 5m 摆动低/高点加同样缓冲
完全无有效结构：多头入场价下方 1.5 个 5m ATR；空头入场价上方 1.5 个 5m ATR

TP1/TP2/TP3 优先按多空方向依次取前方最近的 1h、4h 有效摆动高/低点；同价附近的级别会去重。高周期没有可用前方结构时，才回退到 5m 摆动结构。
结构位不足三档时，使用止损距离 R 延伸下一个严格位于已选目标之外的 R 倍数。
```

因此，5m 决定 Binance 的执行入场、ATR 缓冲和回退结构；高周期优先决定止损与止盈空间。价格计划不参与评分，也不改变候选筛选结果。

页面中止盈止损的百分比都以入场价为基准，并按交易方向调整：止盈始终为正收益百分比，止损始终为负风险百分比。

若 Binance 的 5m K 线、EMA20 或 ATR 不足，评分仍可按其他交易所返回，但 `trade_plan` 不提供价格，并标记为 Binance 数据不足。

### 空间与盈亏比

交易计划在结构位生成后，以止损距离定义 `1R`：

```text
R = abs(入场价 - 止损价)
TPn_R = abs(TPn - 入场价) / R
```

接口返回 `tp1_r`、`tp2_r`、`tp3_r`，页面在每档止盈百分比旁展示对应 R 倍数。最近前方结构位仍保留为 TP1，不会为了提高数字而跳过真实阻力或支撑。

```text
tp1_r >= 1.0: space_status = adequate
tp1_r < 1.0:  space_status = insufficient
```

`insufficient` 表示前方结构空间不足，计划继续展示并标记原因；它不改变评分和候选列表。页面“可做”范围额外要求 `entry_state` 为可做多/可做空、Binance 计划就绪且 `space_status = adequate`，避免把评分成立但首档空间不足的标的当作直接执行机会。

## 可做告警

通知管理页可创建“交易机会可做”规则。该规则评估当前完整评分币种集合，严格复用页面“可做”范围：仅 `可做多`、`可做空`，且 Binance 交易计划就绪、首档空间不少于 `1R`。

规则必须填写止损百分比闭区间 `min_stop_loss_percent..max_stop_loss_percent`，单位为百分比，例如 `2..8`。评估取交易计划 `stop_loss_percent` 的绝对值，含端点匹配；因此多空的止损符号不同不会影响筛选。

同一币种连续达到“可做”且落在止损范围内指定次数后推送，持续满足时不重复推送；已触发机会连续不满足条件达到指定次数后按规则设置发送退出消息，再次进入需重新连续确认。交易机会规则默认连续确认 2 次触发、连续失配 3 次退出，均可在告警管理页配置为 1 至 12 次。已触发候选出现更优同方向入场时，仅在相对上一次已通知计划的改善达到配置阈值后更新通知；阈值单位可选 R 或 Binance 5m ATR，默认 0.5R，设为 0 可关闭更优入场提醒。推送会包含入场、止损、三档止盈、R 倍数、评分及风险原因。

## 页面与接口

新增：

```text
/trade-opportunities
/api/trade-opportunities
```

页面位于主导航“分析”菜单的首项：

```text
分析
  交易机会       /trade-opportunities
  结构评分       /market-structure-score
  合约详情       /coin-detail
  对冲计算器
```

“交易机会”用于筛选和排序可执行标的；“结构评分”保留为趋势、OI、净流入和交易所明细的诊断入口。

默认仅显示数据完整且状态为“可做多、可做空、等待回踩、等待反弹”的标的。表格展示：

```text
币种 | 入场状态 | 趋势状态 | 入场评分 | 趋势分 | 时机分 | 风险分 | 价格 | 交易计划 | 风险原因
```

排序先按入场状态优先级，再按 `abs(entry_score)` 降序。展开行展示价格趋势、OI 结构、净流入占成交额、EMA20 距离、资金费率和风险原因。

## 验收场景

1. 强多趋势但价格偏离 EMA20 超过 1.5 ATR 时，只能显示“等待回踩”。
2. 趋势、OI、净流入同向，回踩确认且风险低时，显示“可做多”。
3. 资金费率、OI 增速或异常波动过热时，风险分必须降低入场评分。
4. 空头及等待反弹逻辑与多头完全镜像。
5. 净流入必须按成交额标准化，不能用绝对金额与 OI 变化直接比较。
6. 数据不足标的不得出现在默认机会列表。
